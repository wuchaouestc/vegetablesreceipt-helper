# 打单助手软件 —— 目录结构与模块职责说明

> 本文是软件著作权登记材料之一，说明 V6 版的源码组织原则、分层模型、模块职责与依赖约束。
> 所有目录名、文件名与接口名均取自实际工程，可直接与源代码对照核验。

---

## 1. 规划目标与不可违反的约束

### 1.1 目标

1. **按职责分区**：同一件事的代码放在一起，看目录名即可判断该去哪改。
2. **依赖单向化**：上层可依赖下层，下层不得反向依赖上层，禁止循环依赖。
3. **根目录收敛**：根目录只保留"被外部机制锁定"的文件，实现代码一律下沉到包目录。
4. **行为零变化**：重构只改组织方式，不改任何业务逻辑与运行结果。

### 1.2 不可违反的约束（决定了什么不能搬）

桌面软件被三类外部机制锁定，这三类文件**必须留在根目录**：

| 约束来源 | 锁定内容 | 代码证据 |
| --- | --- | --- |
| PyInstaller 打包 | 分析入口必须是 `启动器.py` | `打单助手V6.spec`：`Analysis(["启动器.py"], ...)` |
| 补丁装配机制 | 补丁以 `打单助手` 模块的 `__dict__` 为执行命名空间，并注册 `sys.modules["打单助手_原版"]` | `patches/加载.py`：`_执行补丁(布局, 模块.__dict__)` |
| 路径契约 | `路径.程序目录()` 以 `路径.py` 的 `__file__` 为锚点，决定配置、台账、导入副本的落盘位置 | `路径.py`：`return Path(__file__).resolve().parent` |

若把 `打单助手.py` 移入 `app/`，补丁的 `模块.T` / `模块.App` 取不到基类，界面增强全部失效；
若把 `路径.py` 移入子目录，源码运行时数据目录会整体偏移一级，历史台账"消失"。
因此这三个文件的位置属于**架构契约**，不是历史遗留。

## 2. 分层模型

```
┌──────────────────────────────────────────────────────────┐
│  契约层（根目录）                                          │
│  启动器.py  打单助手.py  路径.py  config.py                │
│  settings.json  customers.json  build.py  *.spec  *.bat   │
└───────────────┬──────────────────────────────────────────┘
                │ 依赖
┌───────────────▼──────────┐   ┌───────────────────────────┐
│  子系统层                 │   │  业务领域层  app/          │
│  patches/   界面装配       │──▶│  设置/客户档案/台账/       │
│  handwriting/ 手写识别     │   │  历史/余量/导入落地        │
└───────────────┬──────────┘   └─────────────┬─────────────┘
                │ 依赖                        │ 依赖
┌───────────────▼─────────────────────────────▼─────────────┐
│  基础设施层  core/                                         │
│  ttsb2（OCR + 大模型识别管线）  label_bitmap（渲染与打印）   │
└───────────────┬───────────────────────────────────────────┘
                │ 依赖
┌───────────────▼───────────────────────────────────────────┐
│  平台与外部：标准库 / Pillow / tkinterdnd2 / pywin32        │
│  / 腾讯云 OCR / DeepSeek / 本地结构服务 field_service/      │
└───────────────────────────────────────────────────────────┘
```

**依赖规则**

- 只允许自上而下：契约层 → 子系统层 → 业务领域层 → 基础设施层 → 平台。
- `core/` 不得导入 `打单助手` 或 `patches/`，否则形成循环依赖。
- `app/` 不得导入任何 Tk 控件模块，保证业务规则可被纯逻辑测试覆盖。
- `handwriting/` 不依赖界面，可单独运行（`python -m handwriting`）。

## 4. 模块职责矩阵

### 4.1 业务领域层 `app/`

| 模块 | 单一职责 | 关键接口 | 落盘位置 |
| --- | --- | --- | --- |
| `app_settings` | 配置的唯一读写入口，负责默认值合并与损坏配置兜底 | `读设置` `写设置` `默认设置` | `settings.json` |
| `customer_profiles` | 客户维度的解析与输出规则，含品类归一、编码显示、单位习惯 | `get_profile` `save_profile` `apply_rules` `format_record` | `customers.json` |
| `打单记录` | 逐标签台账，追加写、不覆盖 | `记一张` `查记录` | `打单记录/<客户>/*.txt` |
| `打印历史` | 批次级历史与补打数据来源 | `记一批` `最近批次` | 用户数据目录 |
| `标签余量` | 纸张余量估算，回答"这单够不够打" | `掂量` `扣减` | `标签余量.json` |
| `导入落地` | 拖入图片的归档副本，保留来源以支持回溯 | `落地` | `导入/<日期>/` |

### 4.2 基础设施层 `core/`

| 模块 | 单一职责 | 关键接口 |
| --- | --- | --- |
| `日志` | 全软件日志的唯一出口：路径约定、目录自建、时间戳、轮转、异常吞没 | `日志目录` `日志文件` `写日志` |
| `ttsb2` | 识别管线：腾讯云 OCR 取文字块 → 坐标聚行 → DeepSeek 结构化 → 字段清理/裁决/核算 | `tencent_ocr` `deepseek_parse` `recognize_parallel` `merge_consensus` `cross_check` `build_prompt` |
| `label_bitmap` | 标签可视化：文字排版、条码/二维码、40×30 mm 物理尺寸换算、打印与导出 | `render_label` `render_separator` `print_label` `print_via_usb` `print_via_driver` `save_label_pdf` |

### 4.3 子系统层

| 目录 | 单一职责 | 设计要点 |
| --- | --- | --- |
| `patches/` | 在不改主程序的前提下替换界面与识别行为 | 逐文件 try/except，失败只写诊断日志并退回原行为；装配顺序固定 |
| `handwriting/` | 手写单识别与人工核对闭环 | 不依赖 Tk；判别器复用主流程那次 OCR，不额外计费；证据链可回溯 |
| `field_service/` | 本地结构分析，避免大依赖进入主包 | 独立进程 + HTTP，自带 venv；主程序未启动时自动跳过 |

## 5. 工程设计要点

### 5.1 契约与实现分离

根目录 7 个 `.py` 中，4 个是契约（入口、主模块、路径、密钥），1 个是构建脚本，2 个是密钥模板；
其余 60 个实现文件全部在包目录内。这样"根目录看到什么"就能回答"软件靠什么启动、靠什么定位数据"。

### 5.2 补丁式可演进架构

界面增强不修改主程序，而是由 `patches/加载.py` 按固定顺序把补丁编译进主模块命名空间。
每个补丁独立、可单独删除、失败自动降级。带来的收益是：**新增功能不改动已验证的主流程代码**，
主程序始终可以单独启动（删掉 `patches/` 即退回原版界面）。

### 5.3 失败降级而非崩溃

- 补丁加载失败：捕获异常、写 `补丁加载诊断.log`、继续加载下一个补丁。
- 结构服务不可用：识别主链照常走云端，仅失去结构增强。
- 配置损坏：原样保留文件并告警，不覆盖用户数据。
- 打印机不可用：PDF 通路与 USB/驱动通路互为备份。

### 5.4 数据安全

- 密钥优先级：环境变量 > `config_local.py` > 空占位；真实密钥文件被 `.gitignore` 排除，
  打包产物不内嵌密钥（发布目录内为独立文件，可单独删除后再分发）。
- 构建时对 `settings.json`、`customers.json`、`data/`、台账等用户数据**存在即不覆盖**。
- 台账使用 TSV 而非 CSV，避免 Excel 把 `022.2` 静默改成 `22.2` 导致编码失配。

### 5.5 可验证性

| 手段 | 覆盖范围 | 结果 |
| --- | --- | --- |
| `启动器.py --自检` | 主程序 + 全部补丁装配 | 通过，无补丁异常日志 |
| `unittest discover -s tests` | 业务规则、证据链、复核动作、客户上下文 | 264 个用例通过 |
| `tools/静态导入校验.py` | 全源码 AST 导入解析（含函数内导入） | 89 个文件 / 126 个检查点全部可解析 |
| `docs/工作流核验.py` | 界面与旧流程回归 | 40 个用例 |
| PyInstaller 构建 | 打包产物装配与启动 | 产物自检退出码 0 |

## 7. 新增文件时的归位规则

| 你要加的东西 | 放哪 | 约束 |
| --- | --- | --- |
| 新的业务规则（计价、格式转换、台账字段） | `app/` | 不得导入 tkinter |
| 新的外部服务调用（云 API、本地模型） | `core/` | 密钥从 `config` 取，禁止硬编码 |
| 新的界面增强 | `patches/` 新增一个补丁文件 | 必须 try/except 降级，并在 `加载.py` 注册 |
| 新的识别能力 | `handwriting/` | 不得依赖界面 |
| 新的重依赖服务 | `field_service/` 独立进程 | 自带 venv，通过 HTTP 通信 |
| 新的测试 | `tests/test_*.py` | 用 `unittest`，可被 discover 发现 |
| 新的文档 | `docs/` | 设计类文档与历史报告分开放 |
| 新的工程脚本 | `tools/` | 不得依赖运行时数据 |
