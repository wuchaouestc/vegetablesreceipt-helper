## 二、开发目的与背景

农产品批发环节的采购单长期以**手写单据**或**打印截图**形式流转。一张单据包含几十行
「编码 : 数量 单位」明细，人工录入时存在三个痛点：

1. **效率低**：单张单据 40—50 行，人工逐行录入耗时且易漏行；
2. **易错**：手写体连笔、单位「斤/个」形近，误录直接导致发货错误与对账纠纷；
3. **难追溯**：纸质单据随手丢弃，事后无法核对当时到底录了什么。

本软件把「单据照片 → 结构化清单 → 人工核对 → 按客户规则输出 → 打印标签 → 留台账」
整条链路做成一个桌面程序，目标是在**不牺牲准确率**的前提下把录入环节自动化，
并让每一行数据都可回溯到原始证据。

## 三、主要功能

### 3.1 单据识别

| 功能 | 说明 |
| --- | --- |
| 图片导入 | 支持拖拽与选择文件，图片自动归档副本并记录来源 |
| 普通单识别 | 腾讯云 OCR 提取文字块 → 坐标聚行 → 大模型结构化为明细记录 |
| 手写单识别 | 独立识别通道：版面几何分栏、标题从属、证据链裁决、局部复核 |
| 自动判别 | 依据图像自身特征（编码格式率 + OCR 置信度）自动分流印刷单与手写单 |
| 疑点标注 | 证据不足的字段保留疑点并标红，交人工确认，不静默改值 |

### 3.2 核对与编辑

| 功能 | 说明 |
| --- | --- |
| 清单核对 | 表格展示全部明细，支持多选、批量确认、逐行编辑 |
| 原图对照 | 选中行可定位到原图对应区域，核对有据 |
| 学习复用 | 人工确认结果入库，同一张图再次识别时直接复用，不再调外部接口 |
| 客户规则窗 | 品类归一、单位习惯、备注处理按客户配置，只影响显示与输出 |

### 3.3 输出与打印

| 功能 | 说明 |
| --- | --- |
| 标签排版 | 40×30 mm 标签位图渲染，文字自适应、条码/二维码可选 |
| 双打印通道 | USB 直连与 Windows 驱动通道，前者失败自动回落后者 |
| PDF 导出 | 识别为 PDF 虚拟打印机时，按标签物理尺寸逐张导出 PDF，重名自动加序号 |
| 客户分隔标签 | 按客户插入分隔页，便于分拣 |

### 3.4 台账与运维

| 功能 | 说明 |
| --- | --- |
| 打单台账 | 每张标签追加一行 TSV，按客户分目录，可对账 |
| 打印历史 | 批次级历史，支持会话内补打 |
| 标签余量 | 估算纸张余量，打印前提示"够不够打" |
| 周末模式 | 只写记录不打印，适配非发货日 |
| 缓存清理 | OCR 结果本地缓存，可一键清理 |

## 四、技术特点

### 4.1 双通道识别 + 图像自证分流

不依赖客户档案判断单据类型，而是从**图像本身**取证：当「编码:数量」格式率 ≥ 0.20
且 OCR 置信均值 < 96.0 时判为手写单。该判据由 115 张真实样本（13 张手写 + 102 张印刷）
网格搜索得出，在样本集内零错分且两侧均有余量。判别器复用主流程本来就要做的那次 OCR，
**不产生额外接口费用**；判不准时一律退回普通流程，两条通道都保留疑点，判错不会导致错印。

### 4.2 证据链裁决，改值必留痕

对手写单的每个字段建立证据（同行 OCR 文本、版面几何、模型输出、词典命中、人工确认），
按固定优先级裁决，并遵守五条铁律：

1. 单位（斤/个）不作裁决依据，字形易混，只留对照线索；
2. 数量仅当数字串不同才裁决，小数点位置不同一律不裁决；
3. 品类改值需标题置信度达阈值（默认 90，安全区间 88—95）；
4. 词典只提示，不强制改值；
5. 任何改值必须同时标记「待核对」，不得静默改错。

### 4.3 单据级单位一致性

针对手写「斤」被系统性误读为「个」的行业性难题，软件不只做逐行纠错，而是做**单据级推断**：
以本单人工确认的单位为最高锚点，其次行自身原图硬证据，最后按票源加权投票决定单据单位，
再回填至未读出的行。关键设计在于**折叠护栏比较「硬证据行数」而非总票数**——
模型错读是单方向的，按总票数比等于"谁错得更多谁赢"。

### 4.4 补丁式界面装配

界面增强不修改主程序源码，而由装配器把补丁文件按固定顺序编译进主模块命名空间。
每个补丁独立 try/except：失败只写诊断日志并退回原行为，**绝不因增强代码导致软件起不来**。
删除补丁目录即可退回原版界面，主程序始终可独立运行。

### 4.5 契约与实现分离的源码组织

根目录只保留被外部机制锁定的契约文件（打包入口、主模块命名空间、路径锚点、密钥解析），
其余实现按职责下沉到 `app/`（业务）、`core/`（基础设施）、`handwriting/`（手写子系统）、
`patches/`（界面装配）、`field_service/`（独立服务）。依赖严格单向，禁止循环。
详见《目录结构与模块职责说明》。

### 4.6 多形态分发与数据保护

打包采用暂存目录构建再合并发布，构建过程中对 `settings.json`、`customers.json`、
`data/`、台账等用户数据执行「存在即不覆盖」，避免升级把用户积累的词典、示例、
人工核对的标注冲掉。密钥不内嵌进可执行文件，由程序目录下的独立文件读取，
发布给外部时可单独移除。

## 五、软件架构

四层架构，自顶向下：契约层 → 子系统层 → 业务领域层 → 基础设施层 → 平台与外部服务。

```
契约层（根目录）      启动器.py / 打单助手.py / 路径.py / config.py / build.py / *.spec
        │
子系统层              patches/（界面装配）  handwriting/（手写识别）  field_service/（结构服务）
        │
业务领域层            app/：设置、客户档案、台账、历史、余量、导入落地
        │
基础设施层            core/：ttsb2（识别管线）、label_bitmap（渲染与打印）
        │
平台与外部            标准库 / Pillow / tkinterdnd2 / pywin32 / 腾讯云 OCR / DeepSeek / 本地结构服务
```

各层职责、依赖约束、目录树与模块接口矩阵见《目录结构与模块职责说明》（02 号文件）。

## 九、安装与启动

### 9.1 发布版

```text
打单助手V6/
├── 打单助手V6.exe        主程序，双击启动
├── config_local.py       密钥配置（首次使用需填写）
├── settings.json         应用设置
├── customers.json        客户档案
├── _internal/            运行时依赖与内置资源（含 patches/、field_service/）
├── data/                 词典、示例库、评测产物
├── 导入/                 单据图片副本
└── 打单记录/             台账
```

双击 `打单助手V6.exe` 或 `启动V6.bat` 即可启动。首次使用需在设置页选择标签打印机，
并在 `config_local.py` 填写腾讯云与 DeepSeek 的密钥。

### 9.2 源码版

```bash
python -m pip install -r requirements.txt
copy config_local.example.py config_local.py   # 填入真实密钥
启动源码.bat                                    # 或 pythonw 启动器.py
```

### 9.3 使用流程

1. 选择客户 → 拖入单据图片；
2. 软件自动判别单据类型并识别，输出明细清单；
3. 人工核对标红疑点，必要时打开原图对照；
4. 确认后按客户规则生成输出副本；
5. 打印标签或导出 PDF，台账自动落盘。
