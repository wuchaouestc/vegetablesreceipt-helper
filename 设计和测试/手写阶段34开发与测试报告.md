## 二、阶段 3：证据和复核

方案要求：**完整框、行列关联、候选追踪、统一预算**；通过条件是「关键错误下降，不能裁决则保留疑点」。

### 2.1 新增模块

| 文件 | 职责 |
| --- | --- |
| `handwriting/geometry.py` | 完整框（polygon → 轴对齐包围盒）、分栏、行聚类、标题从属、明细条目解析 |
| `handwriting/evidence.py` | 候选追踪（多来源并列保存）、保守裁决、保留疑点 |
| `handwriting/budget.py` | 统一预算：请求数 / 总时限 / 费用上界 / 分类配额 |
| `handwriting/review.py` | 疑难区域规划、原图裁剪、复核结果合并、迟到响应校验 |
| `handwriting/gate.py` | 对现网 `merge_consensus` / `cross_check` / `fix_category_boundaries` 的门控 + 裁决前候选快照 |
| `handwriting/pipeline.py` | `assisted_recognize()`：手写辅助通道的完整编排（新增，不改动阶段 0—2 的 `recognize()`） |

### 2.2 完整框

现网 `ttsb2.tencent_ocr` 只保留多边形的**首点** x/y。阶段 3 改成返回完整 `polygon` 与 `confidence`，
老缓存（没有 polygon）自动失效并重取一次。新增的 `handwriting/geometry.normalize_blocks()`
兼容三种来源：腾讯云 polygon、现网老缓存的 `{text,x,y}`（退化成点框）、以及直接的 bbox。

### 2.3 行列关联（跨栏先定栏、再定行）

真实单据是手写分栏的，同一 y 上有两三栏的明细。做法：

1. **分栏**：按 x 区间把块归到「与已有成员 x 重合度最高」的一栏；**不把栏区间求并集**——
   否则一个横跨两栏的宽块（如 `粮931:0.5斤()`）会把两栏粘成一栏。
2. **行聚类**：同一栏内按 y 聚行，容差取**块高中位数的一半**（不是相邻间距中位数的一半——
   按间距算的话整页大段空白会把容差撑大，标题会被并进它下面那条明细行）。
3. **标题从属**：标题必须在明细行上方，且与该行的 x 区间**交并比 ≥ 0.3**；
   多个标题都合格时取**离本行最近的上方标题**。
   - 交并比而不是「交集 / 较窄者」：窄标题落在宽行内部时，后者会误判成「完全重合」，
     把很久以前的标题认成当前标题。
4. **跨栏块拆分**：一个块可能含两栏的明细（`1136:1个14:3个`），
   按字符位置把条目映射成各自的 x 子区间，再各自找标题。

### 2.4 候选追踪

每条明细的四个关键字段都保存**并列候选**，来源分别标注：

| 来源 | 内容 |
| --- | --- |
| `model` | 模型读数 |
| `ocr_row` | OCR 行内文字（`1136:1个` 这种同一位置的直接证据） |
| `ocr_heading` | OCR 标题文字（品类的从属关系） |
| `vocabulary` | 词典候选（**只提示不强改**） |
| `review` | 局部复核结果 |

### 2.5 保守裁决规则

| 字段 | 规则 | 依据 |
| --- | --- | --- |
| 编码 | 行内文字与模型不一致且**互为子串**（截断型）→ 采信行内文字；否则保留模型值 + 标疑点 | 同一位置的直接证据 vs 模型自述 |
| 数量 | 数字本身不同（去小数点后不同）→ 采信行内文字；**只是小数点位置不同 → 不裁决** | 小数点是浅笔画，两路都可能错 |
| 品类 | 标题文字与模型不一致，且**标题置信度 ≥ 阈值（默认 90）** → 采信标题；否则保留模型值 + 标疑点 | 草写标题两路都可能读错 |
| 单位 | **任何情况下都不裁决、不单独标疑点**，只留作对照线索 | 实测：OCR 把「斤」读成「个」的比例很高（约 1/4 行），用它裁决会制造大量误报 |
| 缺证据 | 找不到同行文字 → 标「缺少同行证据」，**不改值** | 方案第八节第 1 条 |
| 词典外值 | 只标「词典外品类」等提示，**不判错** | 方案第八节 |

**任何一次改值都同时标成待核对**，不存在静默改写；已确认或手动修改的行不会被覆盖。

### 2.6 统一预算

`handwriting/budget.py` 的 `UnifiedBudget`：请求数 / 总时限 / 费用上界任一超限即**拒绝追加**
（返回 `False`，不抛异常——上层停止追加并转人工，而不是整批失败）；
另有分类配额（每图最多 1 个增强变体、2 个复核区域）。
超时重试同样计入预算。

### 2.7 局部复核

- 疑点行按栏聚成区域，**相邻疑点合并**，区域带上所属标题与上下相邻行；
- 裁剪原图（保留原分辨率，不放大）；
- 追加识别一次，结果按**编码**对回原行，对不上就不猜；
- 合并规则：复核值与 OCR 行内文字一致 → 采信；与模型一致 → 保留模型值但仍标疑点；与两路都不一致 → 保留疑点转人工；
- **迟到响应校验任务 ID、图片版本、行版本**三项，行内容一变，迟到的响应直接丢弃。

### 2.8 旧裁决门控

现网 `cross_check` 在品类合计对上时会**清掉** `_uncertain`，`fix_category_boundaries` 会按合计
把整段行改归到下一个品类——这正是方案说的「旧逻辑先消除疑点」。
`handwriting/gate.py` 在手写辅助通道里做了三件事：

1. 动手前保存**裁决前候选**（`_pre_decision`）；
2. 证据链标出的疑点，合计核对**不能替它消除**；
3. 有同行证据的行，品类归属**不被合计推算改写**。

原流程完全不经过这里，行为不变。

## 三、阶段 4：组合与界面

方案要求：**模式切换、原图对照、冻结验收报告**；通过条件是「满足质量成本门槛，旧流程回归通过」。

### 3.1 模式切换

- `handwriting/modes.py`：`ModeConfig` 快照 + `resolve_mode()` + `mode_for_image()`；
- 界面：`_界面补丁/手写补丁.py` 在图片区加下拉框「原流程 / 手写辅助 / 逐张选择」，
  逐张模式另有两个按钮给清单里选中的图片单独指定；
- **默认「原流程」**——首次升级行为完全不变；
- 设置项（`settings.json` →「识别」段）：
  `手写辅助模式` / `手写局部复核` / `手写词典辅助` / `手写预算请求数` / `手写预算秒数` /
  `手写标题置信阈值` / `手写复核区域数`，`app_settings.py` 的默认设置同步补齐（深合并，只补缺失键）。

### 3.2 线程纪律

模式、仔细模式这些 Tk 状态**一律在主线程 `start_scan` 里读完冻结成不可变快照**，
后台线程只拿快照用；取消/失败/降级都通过现网既有的队列回到主线程。

### 3.3 原图对照

- `handwriting/compare.py`：组装「原图路径 + 区域框 + 裁剪图 + 标题原文 + 行内原文 + 各来源候选 + 建议 + 核对原因」；
- 界面：清单右键新增「原图对照」，弹出窗口显示原图区域截图、原文、逐字段候选（标来源与置信度）、建议与核对原因；
- 核对原因写的是**具体原因**（「数量两路不一致」「缺少同行证据」「品类两路不一致」），
  不是笼统的「低置信度」。

### 3.4 冻结验收报告

`handwriting/frozen.py`：按稳定 row_id / 原图位置一对一核对，产出
关键字段准确率、整行完全正确率、未提示错误、核对负担（待核对比例 / 错误被提示比例 / 正确行误提示比例）、
成本（请求数 / 时限 / 费用），并渲染成 Markdown 报告。

### 3.5 界面补丁接入

`_界面补丁/手写补丁.py` 在 `_界面补丁/加载.py` 中注册（`dict(公共, 主模块=模块)`），
所有入口都套 try/except：补丁出错一律退回原行为，绝不让打单流程停住。
`打单助手V6.spec` 增加 `handwriting.*` 的 hiddenimports，保证发布版 EXE 能找到这个包。

## 五、没做到的 / 已知限制

1. **冻结集只有 2 张图 40 行**，样本小；不做 P95、不做分类别拆分、不下统计显著性结论。
2. **草写标题（马蹄肉、去皮干葱头这类）两路都读不准**，只能保留疑点转人工，本轮不改值——
   这是「不能裁决则保留疑点」的正确表现，不是漏做。
3. **单位（斤/个）在 OCR 上字形易混**，本轮明确不作裁决依据；单位准确率保持 100%，
   代价是单位类的错仍然发现不了。
4. **局部复核只解决「第三路跟哪一路一致」**；两路都不一致时仍保留疑点。
5. **温和图片增强按方案第六节暂缓**，没有实现，`original_image(enhancement=True)` 直接报错，
   不会静默启用。
6. **发布（阶段 5）未做**：暂存构建、实际 EXE 验证、数据保护与回退说明仍是后面的事。
7. `data/annotations`（13 份草稿）与 evaluations 目录（2 份 confirmed）确认状态不一致，
   本轮以 evaluations 目录的人工确认为准，annotations 的历史草稿未改动。
