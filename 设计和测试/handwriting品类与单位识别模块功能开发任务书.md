# handwriting 品类与单位识别模块功能开发任务书

版本：v1.0 · 2026-11-07
状态：开发任务定义，尚未实施。本文不授权默认启用、重新训练、付费云接口批量测试或发布部署。

## 一、目标与边界

在 handwriting 中新增独立字段识别模块，使用本机 PP-OCRv5_mobile_rec 对原图中的品类标题与单位文字区域进行识别，作为腾讯 OCR、DeepSeek 和现有证据链之外的本地候选来源。利用 data 中人工标注建立区域样本、对照评测和后续训练数据出口，使数据积累可验证地服务于识别改善。

首版使用现有预训练模型，默认关闭，仅处理 category、unit；不修改编码、斤数、备注、客户过滤、单位换算或打印格式。不训练新模型，不默认升级 Paddle，不加载完整 PP-Structure 作为字段识别前提。不因增加一个来源就自动清除疑点或覆盖人工结果。

交付应回答：实际调用了什么模型、识别了哪些图片区域、两字段分别改善多少、造成哪些退化、增加多少耗时和内存。服务健康、模型加载成功和字段识别正确必须分别证明。

主进程不 import paddle/paddleocr；重型依赖保留在独立环境。使用本地权重绝对路径和明确模型名，缺失时提示并降级，不在正常识别时静默联网下载或替换模型。服务仅监听回环地址，限制来源图片根、尺寸、像素量和请求体，不接受任意写入路径。

## 四、区域定位与识别流程

流程：原图/版本快照→基础 OCR 完整框与布局→规划字段区域→独立 mobile_rec 批量识别→候选挂入证据链→冲突提示→必要时沿用现有局部复核→人工确认。

1. 品类：优先采用布局标题框，留适量边距且避免相邻栏。一个标题区域只识别一次，结果通过标题从属关系关联多条明细，不能为每行重复请求。
2. 单位：优先采用独立单位文字框；若“编码:数量单位”连在一个 OCR 框内，首版识别整段单行区域，再解析末尾单位。不按字符数猜测像素位置强切最后一个字。
3. 行过长、多个单位、跨栏、标题从属不清或框不完整时返回区域不可用，不从历史斤数推断单位。基础 OCR 漏掉整个区域时记录覆盖缺口；首版不承诺单靠 rec 恢复全页漏检，后续检测模型另立实验。
4. 未识别出“单位”不等于图上没有单位，空值不得因词典常见值而填“斤”。输出层既有单位兜底若继续存在，必须在证据中区分原始空值与后续默认值；改变该业务默认另行验证。
5. 图片使用副本；处理 EXIF、原图/显示/裁剪坐标映射，保留原文件。仅做识别模型必要的适配，不同时引入强二值化、生成式修字等增强。
6. 标注框只用于离线区域能力评测；线上区域必须来自实际定位流程。禁止把验收人工框偷偷作为生产算法输入。

## 五、数据契约、缓存与预算

请求建议包含 schema_version、task_id、image_sha256、原图路径、regions（region_id、field、bbox、row_ids、heading_id）、模型版本和截止时间。坐标采用方向归一后原图像素，bbox 为左上包含、右下排除；转换链需可回溯。row_id 在当前图片内稳定且不按值去重。

每个区域响应包含 region_id、状态、raw_text、rec_score、候选、模型指纹、输入裁剪哈希、耗时、错误码；候选附 source=paddle_mobile_rec、原图框和关联行。rec_score 只是模型原始分数，不等于业务字段正确概率。批量响应允许部分成功，顺序变化按 region_id 回配。

只接收 category/unit 结果；整行识别中出现的编码和数字只作单位解析上下文，不写回编码、斤数。文本解析失败或返回未知单位保留原文并标疑，不强制套词表。

缓存键包括原图及裁剪像素哈希、框、模型/字符表指纹、预处理和解析器版本；原始识别与词典解释分层缓存，后者另含词典 revision。错误不缓存为空成功。跨任务共享同一标题裁剪允许缓存复用，但回填必须核对 task_id、图片版本和行版本。

建议初始限制：每图最多 32 个去重区域、单批最多 16 区域、字段阶段总时限 10 秒，均为可调试验值。统计本地调用/区域次数并纳入总时限及取消控制，不混同云调用费用预算。超限保留未处理区域及原因，不反复重试；取消后忽略晚到结果，不阻塞 Tk 主线程。

## 六、候选与裁决策略

首版采用“观察模式”：产生可见候选、原图区域和冲突原因，不自动替换当前结果。

- 品类与现有结果一致时只增加证据；不把两个共享图像/词典上下文的来源视为完全独立投票。
- 品类冲突时显示原值、Paddle 原文、词典候选及标题区域；词典外品类保留，不跨栏或跨标题改类。
- 单位冲突（尤其斤/个、斤/公斤）必须显示明确核对原因；不换算，不因“常见”选择斤，不使用跨语义危险别名裁决。
- 未知值、空值、框错误或低分返回需可区分。阈值仅在调试集校准，不能调到冻结验收集表现最好。
- 不覆盖人工编辑或确认过的字段；既有 gate、局部复核和单位兜底可能影响结果，必须保存各阶段值以定位影响。

将来若考虑自动修正，必须单独定义并验证“错误改正确、正确改错误”的净收益和适用条件；不属于首版交付。

## 七、data 标注的实际应用

### 7.1 审计与补齐

对 `data/annotations`、`data/learning` 与指定图片建立只读审计：图片路径是否可解析、哈希是否真实匹配、confirmed/complete、复核人、来源组、字段值、框合法性和版本。草稿、路径代替哈希、缺图、坐标缺失、来源不明等分别列清单，不静默升级为有效样本。

现有标注可能只有整行五字段、没有 regions。保留原 JSON，采用版本化扩展或旁挂字段标注，保存 image_sha256、source_group、split、row_id、field、bbox、transcript、normalized_value、visibility、reviewer、confirmed_at。标题框可绑定多行；单位框或单行框须注明标签口径。框内含完整行时 transcript 必须记录完整行文字，不能只把末尾单位当成整图文字标签。

自动定位仅生成草稿，人核对后进入 confirmed。人工确认“看不清”可用于拒识分析，但不能编造训练标签。补框界面可复用现有核对页，导入导出应支持，不要求重建所有历史数据。

### 7.2 首版必须接通的用途

1. 将经确认的字段区域用于独立 rec 能力评测，输出每个区域的原图、真值、原始识别、分数和差异。
2. 将相同图片用于生产自动定位的端到端评测，分开报告定位失败与识字错误；不能用人工框成绩替代上线成绩。
3. 对调试集的已确认数据提取规范品类及单位候选，经过现有词典审核流程收录；同一图片的一次“个→斤”纠错不得变成通用等价规则。
4. 保存新模块识别错误及人工纠正、原始字段区域和模型指纹，形成后续可复用样本，不只保存最终业务值。
5. 导出与安装版本兼容的训练清单（裁剪图→完整文字标签）及来源分组；首版仅导出并校验，不执行训练或替换权重。单纯增加标注不会自动修改模型参数。

`confirmed_examples` 只有文本无图/无框时可供人工参考，不能直接作为视觉训练样本。验收集答案不得用于词典生成、示例检索、阈值调节或提示词；训练、调试、验收副本与同源裁剪不得跨集合。

## 八、指定测试目录与分组

测试和验证图片根固定为 `导入/2026-10-18`，保持原目录及文件不变。阶段 0 生成版本化 manifest，记录相对路径、文件/像素哈希、尺寸、EXIF、来源组、文档类型和困难类型。与 data 既有素材按哈希匹配，近似图只作复核建议，不能自动认定不同文件就是独立单据。

来源组由人工确认，同一单的原图、截图、局部及增强图必须同组。先确定调试组和冻结验收组再改规则；13 个文件若不足以覆盖关键场景，应报告样本不足并补充素材，不宣称普遍有效。重复图片不能同时用于学习与验收；冻结组的历史词典/示例污染需要审计并使用独立词典快照。

对照组：A 当前 handwriting 固定基线；B 仅增加 Paddle 字段候选观察模式；C 人工确认框下的独立模型诊断。A/B 保持云端输入、词典、模型、客户及其余参数一致，可重放固定的基础 OCR/模型响应以隔离字段模块影响；真实端到端云请求另行记录随机波动和调用授权，不因本任务书自动批量执行付费请求。

## 九、测试及验收标准

| 层次 | 必测内容与通过要求 |
| --- | --- |
| 字段单测 | 框越界、方向、整行单位解析、标题复用、未知单位、空响应、乱序批量、模型缺失、旧服务、取消晚到；结果关联正确且不串行 |
| 真实模型 | 明确 mobile_rec 权重与环境，至少一次真实字段请求成功；健康检查不能替代推理；无网络下载情况下可复现 |
| 字段质量 | 品类、单位分别报告精确匹配率、字符错误率、定位覆盖率、拒识率和冲突检出；不能只算模型愿意回答的区域 |
| 业务质量 | 逐例列出原错→建议对、原对→建议错；统计人工接受后的改善与误导，不用观察模式未改值宣称最终准确率提升 |
| 回归 | 编码/斤数/备注不被模块写入；不漏行不合并重复行；非手写原流程、关闭模块、词典隔离、确认与打印、日志展开/收起正常 |
| 性能 | 分别报告冷启动与热推理、每图总耗时、区域数、超时、RSS 峰值、权重体积及新增依赖体积；建议热路径额外耗时中位数≤3秒，10秒预算内完成或正常退出 |
| 运行产物 | 暂存 EXE 实测能发现独立环境和模型、请求命中新端点、候选能显示；不覆盖配置/数据，不强关含结果窗口 |

观察模式验收至少要求：所有有效区域可追踪；首版不自动改值；失败可降级且有原因；固定输入回归不因字段模块改动编码/斤数/备注；真实样本中存在经人工确认的有效候选，否则只交付实验报告，不将其作为已改善的业务功能默认启用。

性能值为建议门槛，应在阶段 0 测量后冻结；超出时优化或保持关闭，不能隐瞒冷启动。准确率提升目标在基线和有效样本量确定后写入冻结验收清单，不预先承诺比例；样本不足只能给逐例结论。

## 十一、任务完成定义

交付代码时必须同时提供可运行模块、数据应用工具、经人工确认的指定目录验证材料、失败/退化案例及回退说明。安装模型、健康接口就绪、单元测试通过或只生成标注文件均不能单独视为任务完成；若样本、区域标注或真实推理仍缺失，应明确阻塞项及已验证范围。

本任务书本轮仅编写与核查，未开发模块、未训练、未改配置、未启动识别试验、未部署。
